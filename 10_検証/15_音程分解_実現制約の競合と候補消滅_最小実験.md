# 検証記録：音程分解・実現制約の競合と候補消滅

*対象：音度から具体音への実現で、制約が候補を分岐・消滅させる位置を記録する*
*状態：DRAFT v0.1 / 音程分解Module候補*
*実装：`10_検証/constraint_competition_observation.py`*

---

## ■ 0. 検証目的

14では、次の段階を分離した。

```text
B_realization
  ↓ Γ_spelling
綴り付き候補集合
  ↓ B_range_projection
声域境界を通過した候補集合
  ↓ Γ_ordering
上下関係を満たす候補対
  ↓ Γ_select
具体的target
```

ただし、14の実装では候補対が一つも残らない場合、`Γ_select`へ渡す前に例外として停止する。
15では、この停止を一つの失敗として隠さず、候補がどの段階で消えたかを観測する。

```text
候補生成
  ↓
声域境界の投影（B_range_projection）
  ↓
上下関係の適用（Γ_ordering）
  ↓
候補が残れば選択
  ↓
残らなければ既知の診断結果として保持
```

今回の問いは、「同じ目標音度と同じ候補生成規則でも、実現境界や関係制約の置き方によって、選択可能なtarget、許容候補ゼロ、片側候補ゼロへ分岐するか」である。

---

## ■ 1. 14から引き継ぐ構造

対象は14と同じ、F♯ major内の次の目標音度である。

```text
lower：7 → 1
upper：4 → 3
```

`Γ_spelling`の入力は、14と同じ候補オクターブで固定する。

```text
lower：F♯3 / F♯4 / F♯5
upper：A♯3 / A♯4 / A♯5
```

ここで、`A4`／`d5`の音程ラベルからtargetを生成する処理は追加しない。目標音度は13から14へ引き継いだ`M_B^learned`側の結果として扱い、15はその後段の制約競合だけを観測する。

15の実験器は、14最新版の`degree_to_pitch_realization.py`に定義された`RealizationBoundary`を依存型として使用する。したがって、検証はリポジトリのルートから実行し、14と15を同じ正本系列で扱う。

---

## ■ 2. 三つの境界条件

### 2.1 通常ケース

14と同じ広い声部範囲を置く。

```text
生成候補 → 複数の許容候補対 → Γ_select → F♯4–A♯4
```

### 2.2 上下関係の競合

候補生成は通常ケースと同じだが、範囲を次のように狭める。

```text
lower：F♯5だけ
upper：A♯4だけ
```

各声部には候補が残る。しかし、`lower < upper`を満たさないため、許容候補対はゼロになる。

```text
F♯5 / A♯4
  ↓ lower < upper に失敗
許容候補対なし
```

### 2.3 音域の競合

下声の範囲を`G3`だけに置く。

```text
生成候補：F♯3 / F♯4 / F♯5
下声範囲：G3–G3
```

この範囲には生成候補が一つも入らない。したがって、上下関係を検査する前に下声候補集合が空になる。

---

## ■ 3. 観測構造

15では、14の段階を次の観測値として保持する。

```text
generated_candidates
  Γ_spelling直後の候補

filtered_candidates
  B_range_projectionを通過した候補

admissible_pairs
  Γ_orderingを通過した候補対

selected
  Γ_selectが選んだ具体音。候補対が残った場合だけ存在する

failure_stage / failure_reason
  候補が消えた段階と理由
```

空集合の診断名は、次のように分ける。

```text
constraint_no_candidate
  B_range_projectionで片側の候補集合が空になった

no_admissible_candidate
  B_range_projection後には候補が残ったが、Γ_orderingで候補対が空になった
```

いずれも、現在置いた`B`と`Γ`のもとでの既知の候補消滅である。空集合そのものを未回収の`ξ`や対象全体の破綻とは扱わない。

これにより、次を区別する。

```text
候補生成に失敗した
片側の範囲で候補が消えた
両側には候補があるが、関係制約で対が消えた
候補対はあるが、選択規則が別候補を選んだ
```

最後の「選択規則が別候補を選んだ」は14の`Γ_select`比較に属し、15の候補消滅とは別の事象として扱う。

---

## ■ 4. 検証結果

コードで次を確認する。

```text
1. 三ケースとも、Γ_spelling直後の生成候補は同じである
2. 通常ケースでは、許容候補対が残り、F♯4–A♯4が選ばれる
3. 上下関係の競合では、B_range_projection後も両声部の候補は残る
4. Γ_orderingで上下関係を満たす候補対がゼロになる
5. 音域の競合では、B_range_projectionで下声候補集合が空になる
6. 候補対がない場合、Γ_selectは呼ばれず、selectedは空として保持される
7. 上下関係の競合と音域の競合は、同じ診断へ圧縮されない
```

圧縮すると、次のようになる。

```text
target degree
  ↓ B_realization / Γ_spelling
generated candidates
  ↓ B_range_projection
filtered candidates
  ↓ Γ_ordering
admissible pairs
  ├─ 残る → Γ_select → concrete target
  ├─ B_range_projectionで消える → constraint_no_candidate
  └─ Γ_orderingで消える → no_admissible_candidate
```

## ■ 5. この実験から言えること

```text
1. 同じ目標音度と同じ候補生成規則でも、実現境界の違いによって結果が分岐する。
2. 「候補がない」は、生成前の不在ではなく、範囲フィルタ後の消滅である場合がある。
3. 各声部に候補が残っていても、声部間の関係制約によって候補対が消えることがある。
4. Γ_selectは、許容候補対が残る場合にだけ具体音を選択する。
5. 候補消滅の段階と理由を保持すれば、targetが選ばれなかったことを一つの原因へ圧縮せずに済む。
6. 既知の制約で空集合になったことと、その後の再探索方針が未定義であることを分離できる。
```

ここで見えているのは、具体音の実現が単なる「候補から一つを選ぶ」操作ではなく、候補集合が制約の順序に沿って縮退し、場合によっては空集合になる過程だということである。

## ■ 6. RDL上の保存構造と未解決ξ

### 保存構造

```text
同じ target degree
同じ Γ_spelling
異なる B_realization / B_range_projection / Γ_ordering 条件
  ↓
選択可能な候補、候補対消滅、片側候補消滅へ分岐
```

### 未解決ξ

```text
どの声部範囲が実際の演奏・作曲で妥当か
上下関係を常に strict に要求するか
候補が空になった場合にBを引き直す条件
制約を緩和する順序
別の候補生成Γへ切り替える条件
制約競合時に人間がどの候補を再探索するか
```

ここでの`ξ`は、既知の空集合そのものではなく、空集合の後にどの再探索方針を採るかが未定義である部分を指す。これらは15の実験用境界を越えるため、`B`や`Γ`の一般定義へ昇格させない。

## ■ 8. まだ言えないこと

```text
制約が厳しいほど音楽的に悪いこと
候補を一つにできることが正しいこと
範囲・上下関係が音楽一般に共通すること
空集合が実際の作曲上の「不可能」を意味すること
constraint_no_candidateが直ちにBの引き直しを要求すること
no_admissible_candidateが直ちにΓの変更を要求すること
既知の候補消滅を対象そのものの破綻とみなすこと
```

今回の空集合は、今回置いた境界と規則のもとでの候補消滅を意味するだけである。

## ■ 9. 暫定結論

15では、14の実現段階において候補が消える位置を分解した。

```text
候補生成
  ↓
声域境界の投影（B_range_projection）
  ↓
上下関係（Γ_ordering）
  ↓
選択
```

同じ`7→1`・`4→3`と同じ候補生成でも、境界条件が変われば、具体targetの選択、許容候補対の消滅、片側候補の消滅へ分岐する。

したがって、14の

```text
候補集合 → 許容候補対 → 選択
```

は、候補が常に残ることを前提にした直線ではない。候補集合と制約の関係を保持したまま、空集合になった地点を`failure_stage`と`failure_reason`による既知の診断結果として記録する必要がある。

今回の実験では、音域で候補が消えた場合を`constraint_no_candidate`、音域を生き残った候補から順序を満たす対が作れない場合を`no_admissible_candidate`とした。ここからBを引き直すか、制約を緩和するか、別の候補生成Γへ移るかは未解決ξとして残る。

15は、実現制約の競合と候補消滅を扱う最小Moduleとして閉じる。
