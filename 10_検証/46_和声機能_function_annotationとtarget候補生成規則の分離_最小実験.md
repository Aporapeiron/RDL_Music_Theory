# 検証記録：和声機能・function annotationとtarget候補生成規則の分離

*対象：function annotation candidateからtarget候補集合を作る規則を、annotationそのものと分けて置けるか*  
*状態：DRAFT v0.1 / 42〜45循環分解後のξ_target_candidate_generation最小検証*  
*実装：`10_検証/harmonic_function_target_generation_rule_boundary.py`*

---

## ■ 0. 検証目的

42〜45では、次の循環候補を自動閉包させずに分解した。

```text
function annotation
  ≠ target candidate generation
  ≠ target selection
  ≠ target degree planning
  ≠ concrete pitch realization
  ≠ next key/context interpretation
```

46では、このうち最初の未解決ξである `ξ_target_candidate_generation` を最小に掘る。

ただし、`dominant_candidate → C major` のような固定規則を、function annotationそのものへ埋め込まない。

今回確認するのは、次である。

```text
function annotation candidate
  + key context
  + Γ_target_candidate_generation_fixture
  ↓
generated target candidate set
```

ここで重要なのは、次の三つを分けることである。

```text
function annotation candidate
  ≠ Γ_target_candidate_generation_fixture
  ≠ generated target candidate set
```

---

## ■ 1. 固定する最小入力

42と同じ経路から、次のfunction observationを得る。

```text
G major triad
  + C major
  ↓
degree 5
  ↓
function annotation = dominant_candidate
```

この時点ではtargetは未生成である。

```text
generated target = None
```

## ■ 2. 外部から与える生成規則

今回は、fixture用の限定的な生成規則を外部から与える。

```text
Γ_target_candidate_generation_fixture:
  name = dominant_in_c_major_fixture_targets
  scope = fixture_limited_not_general_harmony
```

これは一般的な和声機能規則ではない。

```text
Γ_target_candidate_generation_fixture
  ≠ dominant_candidate
  ≠ 一般和声規則
```

---

## ■ 3. 最小ケース

### 3.1 生成規則なし

```text
dominant_candidate
  + C major
  + Γ_target_candidate_generation_fixtureなし
  ↓
status = no_generation_rule
target candidate set = empty
```

function annotation candidateだけでは、target候補集合は生成されない。

### 3.2 生成規則あり

```text
dominant_candidate
  + C major
  + Γ_target_candidate_generation_fixture
  ↓
target candidate set = {C major, A minor}
```

ここで `{C major, A minor}` は、今回のfixture規則によって生成された候補集合である。

これはselected targetではない。

```text
generated target candidate set
  ≠ selected target
```

### 3.3 規則の適用外

同じfixture規則を、`G major`内の`tonic_candidate`へ接続しても候補は生成しない。

```text
G major triad
  + G major
  ↓
tonic_candidate
  + dominant_in_c_major_fixture_targets
  ↓
status = rule_not_applicable
target candidate set = empty
```

これは、生成規則がfunction annotationだけでなく、限定されたcontext条件も読んでいることを示す。

## ■ 4. 観測結果

| function annotation | key context | generation rule | status | target candidates | generated by function annotation alone |
|---|---|---|---|---|---|
| `dominant_candidate` | `C major` | `None` | `no_generation_rule` | empty | `false` |
| `dominant_candidate` | `C major` | `dominant_in_c_major_fixture_targets` | `generated_candidate_set` | `C major`, `A minor` | `false` |
| `tonic_candidate` | `G major` | `dominant_in_c_major_fixture_targets` | `rule_not_applicable` | empty | `false` |

確認できたこと。

```text
function annotation candidate
  ≠ target candidate generation rule

target candidate generation rule
  ≠ generated target candidate set

generated target candidate set
  ≠ selected target
```

## ■ 5. Module責務の確認

今回の接続は、次のように分かれる。

```text
和声機能Module / 42:
  function annotation candidateを渡す

target候補生成境界 / 46:
  外部fixtureとしてΓ_target_candidate_generation_fixtureを受け取る
  function annotation candidateとkey contextを読み、候補集合を作る

選択境界 / 43:
  今回は未接続
```

46は、43で外部入力していたtarget候補集合の手前に、限定的な生成規則を置く検証である。

ただし、生成規則はfixtureであり、function annotationそのものでも一般的な和声規則でもない。

## ■ 6. まだ言えないこと

今回の検証から、次は言えない。

```text
dominant_candidateが常にC majorやA minorを候補にすること
dominant_candidateからtarget候補集合が一般的に生成できること
deceptive resolutionの一般規則

selected targetが決まること
target degree planが決まること
```

`Γ_target_candidate_generation_fixture` は、C major内のdominant_candidateを見るための限定fixtureである。

これらは未解決ξとして残す。

## ■ 7. 暫定結論

46では、function annotation candidateの後段に、外部から与えた限定的なtarget候補生成規則を接続できることを確認した。

```text
dominant_candidate
  + C major
  + Γ_target_candidate_generation_fixture
  ↓
generated target candidate set = {C major, A minor}
```

ただし、この生成はfunction annotation candidate単独から生じたものではない。

今回のfixtureでは、生成規則の適用可能性もfunction annotation単独では決まらず、key contextとの組に依存する。

```text
function annotation candidate
  ≠ Γ_target_candidate_generation_fixture
  ≠ applicability condition
  ≠ generated target candidate set
```

また、生成されたtarget候補集合はselected targetではない。

```text
generated target candidate set
  ≠ selected target
```

したがって46は、42〜45で空けていた `ξ_target_candidate_generation` に、限定fixtureを置いた場合でも、annotationとgenerationの分離が保てることを確認する最小例である。
