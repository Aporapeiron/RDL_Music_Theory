# 検証記録：基層-learned bridge・Γ_bridge差し替えによるbridge候補分岐

*対象：同じhuman-side response differenceと同じlearned category候補集合で、Γ_bridgeだけを差し替えたときbridge候補が分岐する条件*  
*状態：DRAFT v0.1 / 57 bridge境界検証後のΓ差し替え最小検証*  
*実装：`10_検証/base_to_learned_bridge_gamma_variation.py`*

---

## ■ 0. 検証目的

57では、human-side response differenceからlearned categoryを直生成せず、外部候補集合と`Γ_bridge`を接続した場合だけbridge候補が観測されることを確認した。

58では、同じhuman-side response difference、同じexternal learned category candidatesを固定し、`Γ_bridge`だけを差し替える。

```text
same human-side response difference
  + same external learned category candidates
  + different Γ_bridge_fixture
  ↓
different bridge candidates
```

ここで確認するのは、bridge候補がresponse differenceの属性でも、learned候補集合の属性でもなく、`response difference × learned candidate set × Γ_bridge` の関係として分岐することである。

---

## ■ 1. 固定するhuman-side response difference

57と同じA2系のhuman-side response differenceを使う。

```text
human-side response difference:
  label = A2 behavioral discriminability difference
  source_base_candidate = frequency_difference_to_behavioral_discriminability_candidate
  response_axis = behavioral_discriminability
  lower_response = low_discriminability
  higher_response = high_discriminability
  generated_learned_category = None
```

これは弁別応答差であり、pitch categoryや音程認識ではない。

---

## ■ 2. 固定するexternal learned category candidates

今回は候補集合も固定する。

```text
external learned category candidates:
  same_pitch_relation_label_candidate
  different_pitch_relation_label_candidate
  uncertain_pitch_relation_label_candidate
```

これらはすべて外部fixture候補であり、response differenceから生成しない。

```text
external learned category candidates
  ≠ generated by response difference
```

---

## ■ 3. 差し替えるΓ_bridge

二つのfixture用Γを用意する。

```text
Γ_bridge_discriminability_to_difference_label_fixture:
  A2 behavioral discriminability difference
  + external candidates
  → different_pitch_relation_label_candidate をbridge候補として読む
```

```text
Γ_bridge_discriminability_to_uncertain_label_fixture:
  A2 behavioral discriminability difference
  + external candidates
  → uncertain_pitch_relation_label_candidate をbridge候補として読む
```

どちらも一般的なcategory generation ruleではない。半音知覚、音程認識、音名生成の規則でもない。

---

## ■ 4. 最小ケースの比較

### 4.1 difference label Γ

```text
same response difference
+ same external candidates
+ Γ_bridge_discriminability_to_difference_label_fixture
↓
bridge candidate = different_pitch_relation_label_candidate
```

### 4.2 uncertain label Γ

```text
same response difference
+ same external candidates
+ Γ_bridge_discriminability_to_uncertain_label_fixture
↓
bridge candidate = uncertain_pitch_relation_label_candidate
```

両方とも、learned categoryの確定や選択済み音楽解釈は生成しない。

---

## ■ 5. 観測結果

| human-side response difference | external candidates | Γ_bridge | bridge candidate | selected musical interpretation |
|---|---|---|---|---|
| same | same | difference label fixture | `different_pitch_relation_label_candidate` | `None` |
| same | same | uncertain label fixture | `uncertain_pitch_relation_label_candidate` | `None` |

確認できたこと。

```text
same human-side response difference
same external learned category candidates
different Γ_bridge
↓
different bridge candidates
```

したがって、bridge候補はhuman-side response difference単独の属性ではない。

```text
bridge candidate
  ≠ human-side response difference の属性
  ≠ learned category candidate set の属性
  ≠ selected musical interpretation
```

---

## ■ 6. Module責務の確認

今回の接続は、次のように分かれる。

```text
基層候補側:
  同じhuman-side response differenceを渡す

learned側:
  同じlearned category候補集合を外部入力として渡す

Γ_bridge:
  bridge候補の読み方を差し替える

bridge候補:
  Γ_bridge差によって分岐する

中核音楽理論:
  今回は未接続
```

したがって、bridge候補分岐は、response側の値だけでもlearned候補集合だけでも決まらない。

---

## ■ 7. まだ言えないこと

今回の検証から、次は言えない。

```text
どちらのbridge候補が正しいlearned categoryであること
bridge候補がselected musical interpretationであること
Γ_bridgeの採用条件が決まったこと
周波数弁別からpitch categoryが生成されたこと
周波数弁別からsemitone categoryが生成されたこと
音程認識が説明されたこと
文化差・学習差・命名体系差が説明されたこと
```

また、今回の二つの`Γ_bridge`はfixture用であり、一般的なbase-to-learned mappingではない。

---

## ■ 8. 暫定結論

58では、同じhuman-side response differenceと同じexternal learned category candidatesでも、`Γ_bridge`を差し替えるとbridge候補が分岐することを確認した。

```text
bridge candidate
  = C(human-side response difference, external learned category candidates; Γ_bridge_fixture)
```

ただし、これはfixture内の限定表現である。bridge候補はlearned category生成でも、音楽解釈選択でもない。

次に進むなら、same response difference、same Γ_bridgeで、external learned category candidatesを差し替えるとbridge候補が分岐または消滅するかを見る。
