# 検証記録：和声機能・history差し替えによるtarget候補集合分岐

*対象：同じcurrent function observationと同じ生成規則でも、historyが変わるとtarget候補集合が変わる条件*  
*状態：DRAFT v0.1 / 46〜48構造抽出後のξ_history_sensitive_generation最小検証*  
*実装：`10_検証/harmonic_function_generation_history_variation.py`*

---

## ■ 0. 検証目的

46〜48では、target候補集合がfunction annotation単独の属性ではなく、function observationと `Γ_target_candidate_generation` の関係として生じることを確認した。

49では、同じcurrent function observationと同じ生成規則を固定したまま、historyだけを差し替える。

```text
same current function observation
  + same Γ_target_candidate_generation_fixture
  + different history
  ↓
different generated target candidate sets
```

ここでhistoryはselected targetではない。候補生成の追加入力として扱う。

---

## ■ 1. 固定するcurrent function observation

current function observationは46と同じものに固定する。

```text
G major triad
  + C major
  ↓
degree 5
  ↓
function annotation = dominant_candidate
```

今回は、current function observationを変えない。

---

## ■ 2. 固定する生成規則

今回は一つのhistory-sensitive fixture規則を使う。

```text
Γ_history_sensitive_fixture:
  dominant_candidate + C major + ordinary_preparation
    → {C major}

  dominant_candidate + C major + deceptive_setup
    → {C major, A minor}
```

これは一般和声規則ではない。history依存の候補生成境界を観測するための限定fixtureである。

---

## ■ 3. 差し替えるhistory

二つのhistory fixtureを用意する。

```text
History A:
  label = ordinary dominant preparation
  local_pattern = ordinary_preparation

History B:
  label = deceptive setup
  local_pattern = deceptive_setup
```

historyは、今回の検証ではcurrent function observationとは別入力である。

---

## ■ 4. 最小比較

### 4.1 ordinary preparation

```text
dominant_candidate + C major
  + Γ_history_sensitive_fixture
  + ordinary_preparation
  ↓
generated target candidate set = {C major}
```

### 4.2 deceptive setup

```text
dominant_candidate + C major
  + Γ_history_sensitive_fixture
  + deceptive_setup
  ↓
generated target candidate set = {C major, A minor}
```

同じcurrent function observation、同じ生成規則でも、historyが変わると候補集合が変わる。

---

## ■ 5. 観測結果

| current function observation | generation rule | history | generated target candidates | generated by function annotation alone |
|---|---|---|---|---|
| `dominant_candidate / C major` | `history_sensitive_dominant_fixture_targets` | `ordinary_preparation` | `C major` | `false` |
| `dominant_candidate / C major` | `history_sensitive_dominant_fixture_targets` | `deceptive_setup` | `C major`, `A minor` | `false` |

確認できたこと。

```text
same current function observation
  + same Γ_target_candidate_generation_fixture
  + different history
  ↓
different generated target candidate sets
```

したがって、target候補集合はcurrent function observationの属性でも、生成規則単独の出力でもない。

---

## ■ 6. Module責務の確認

今回の接続は、次のように分かれる。

```text
和声機能Module:
  current function observationを渡す

history境界:
  外部fixtureとしてhistoryを渡す

target候補生成境界:
  同じΓ_history_sensitive_fixtureを適用する
  current observationと、
  今回参照するhistory.local_patternに応じて候補集合を生成する

選択境界:
  今回は未接続
```

49では、target候補集合を生成するが、selected targetは作らない。

---

## ■ 7. まだ言えないこと

今回の検証から、次は言えない。

```text
ordinary_preparationやdeceptive_setupをどう観測するか
historyをどの長さ・粒度で保持するか
history-sensitive fixtureが一般和声規則であること
A minor候補を含める一般条件
生成規則をどのcontrollerが選ぶか
selected targetが決まること
```

historyはfixtureであり、一般的・文脈依存な `ξ_history_sensitive_generation` は未解決である。

---

## ■ 8. 暫定結論

49では、同じcurrent function observationと同じ生成規則でも、historyを変えると生成されるtarget候補集合が変わることを確認した。

```text
dominant_candidate + C major + Γ_history_sensitive_fixture + ordinary_preparation
  → {C major}

dominant_candidate + C major + Γ_history_sensitive_fixture + deceptive_setup
  → {C major, A minor}
```

これにより、target候補集合はcurrent function observationの内在属性ではなく、current observation、history、生成規則の関係として生じることを確認した。

今回のfixtureでは、生成規則がhistoryのうち `local_pattern` を参照した。

```text
generated target candidate set
  = C(current function observation, history.local_pattern; Γ_target_candidate_generation_fixture)
```

ただし、これはfixture内の限定表現であり、一般和声規則ではない。history全体のどの軸を読むかは未解決ξとして残る。
