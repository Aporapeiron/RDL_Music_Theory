# 検証記録：和声機能・context差し替えによるtarget候補集合分岐

*対象：同じfunction annotation labelと同じ生成規則でも、key contextが変わるとtarget候補集合が変わる条件*  
*状態：DRAFT v0.1 / 47の後続検証*  
*実装：`10_検証/harmonic_function_generation_context_variation.py`*

---

## ■ 0. 検証目的

47では、同じfunction annotation candidateと同じkey contextでも、生成規則を差し替えるとtarget候補集合が変わることを確認した。

48では、生成規則を固定し、key contextだけを変える。

```text
same function annotation label
  + different key context
  + same Γ_target_candidate_generation_fixture
  ↓
different generated target candidate sets
```

ここで固定するのは `function annotation label = dominant_candidate` である。同一の `FunctionObservation` object を固定するわけではない。

---

## ■ 1. 固定するfunction annotation label

二つのfunction observationを用意する。

```text
G major triad
  + C major
  ↓
dominant_candidate

D major triad
  + G major
  ↓
dominant_candidate
```

どちらもfunction annotation labelは `dominant_candidate` である。

ただし、chord candidateとkey contextは異なる。

---

## ■ 2. 固定する生成規則

今回は一つの文脈依存fixture規則を使う。

```text
Γ_context_sensitive_fixture:
  C major + dominant_candidate
    → {C major, A minor}

  G major + dominant_candidate
    → {G major, E minor}
```

これは一般和声規則ではない。context依存の生成境界を観測するための限定fixtureである。

---

## ■ 3. 最小比較

### 3.1 C major context

```text
dominant_candidate
  + C major
  + Γ_context_sensitive_fixture
  ↓
generated target candidate set = {C major, A minor}
```

### 3.2 G major context

```text
dominant_candidate
  + G major
  + Γ_context_sensitive_fixture
  ↓
generated target candidate set = {G major, E minor}
```

同じfunction annotation label、同じ生成規則でも、key contextが変わると候補集合が変わる。

---

## ■ 4. 観測結果

| function annotation label | key context | generation rule | generated target candidates | generated by function annotation alone |
|---|---|---|---|---|
| `dominant_candidate` | `C major` | `context_sensitive_dominant_fixture_targets` | `C major`, `A minor` | `false` |
| `dominant_candidate` | `G major` | `context_sensitive_dominant_fixture_targets` | `G major`, `E minor` | `false` |

確認できたこと。

```text
same function annotation label
  + different key context
  + same Γ_target_candidate_generation_fixture
  ↓
different generated target candidate sets
```

したがって、target候補集合はfunction annotation labelの属性ではない。

---

## ■ 5. Module責務の確認

今回の接続は、次のように分かれる。

```text
和声機能Module:
  function observationを渡す
  今回比較するannotation labelはdominant_candidateで一致する

音階・調Module:
  function observation内のkey contextとして
  C major / G majorを渡す

target候補生成境界:
  同じΓ_context_sensitive_fixtureを適用する
  contextに応じて候補集合を生成する

選択境界:
  今回は未接続
```

48では、target候補集合を生成するが、selected targetは作らない。

---

## ■ 6. まだ言えないこと

今回の検証から、次は言えない。

```text
context_sensitive fixtureが一般和声規則であること
C majorでA minor候補を含める一般条件
G majorでE minor候補を含める一般条件
生成規則をどのcontrollerが選ぶか
key contextがどの時点で確定するか
selected targetが決まること
```

生成規則はfixtureであり、一般的・文脈依存な `ξ_target_candidate_generation` は未解決である。

---

## ■ 7. 暫定結論

48では、同じfunction annotation labelと同じ生成規則でも、key contextを変えると生成されるtarget候補集合が変わることを確認した。

```text
dominant_candidate + C major + Γ_context_sensitive_fixture
  → {C major, A minor}

dominant_candidate + G major + Γ_context_sensitive_fixture
  → {G major, E minor}
```

これにより、target候補集合はfunction annotation labelの内在属性ではなく、annotation、context、生成規則の関係として生じることを、47とは別軸で確認した。

```text
generated target candidate set
  = C(function annotation label, key context; Γ_target_candidate_generation_fixture)
```

ただし、これはfixture内の限定表現であり、一般和声規則ではない。

46〜48で、`ξ_target_candidate_generation` は次の形で少しだけ見えた。

```text
function annotation
  ≠ generation rule
  ≠ applicability condition
  ≠ generated target candidate set

generated target candidate set
  = C(function annotation, context; Γ_generation)
```
