# 検証記録：和声機能・target候補集合と選択境界

*対象：function annotation候補と、外部入力されたtarget候補集合・選択規則の境界*  
*状態：DRAFT v0.1 / 42の後続検証*  
*実装：`10_検証/harmonic_function_target_candidate_boundary.py`*

---

## ■ 0. 検証目的

42では、同じ和音候補に異なるkey contextを接続し、degree annotationと限定的なfunction annotation候補が分岐することを確認した。

ただし42では、targetを生成しなかった。

43では、function annotation候補にtarget候補集合を外部入力として接続し、候補集合の観測と選択の境界を検査する。

```text
function annotation candidate
  + externally supplied target candidate set
  ↓
target candidates observed
  ↓
Γ_selectなし
  ↓
underdetermined

target candidates observed
  + Γ_select
  ↓
selected target
```

ここでも、function annotationからtarget候補集合を生成しない。

---

## ■ 1. 固定する最小入力

42と同じく、次のfunction observationを使う。

```text
G major triad
  + C major
  ↓
degree 5
  ↓
dominant_candidate
```

この`dominant_candidate`はtarget生成器ではない。

target候補集合は外部から与える。

```text
externally supplied target candidates:
  - C major
  - A minor
```

この二候補は、今回のfixtureであり、一般的なdominant解決候補集合ではない。

---

## ■ 2. BとΓ

今回の境界は次の通り。

```text
B_target_candidate_boundary:
  function annotation candidate
  externally supplied target candidate set
  optional selection policy
```

使うΓは、候補観測と選択を分ける。

```text
Γ_observe_target_candidates:
  externally supplied target candidate set
  → target candidates observed

Γ_select:
  target candidates + selection policy
  → selected target
```

ここで置かないもの。

```text
Γ_target_generation_from_function
Γ_voice_leading_generation
Γ_next_key_interpretation
```

---

## ■ 3. 最小ケース

### 3.1 選択規則なし

```text
dominant_candidate
  + {C major, A minor}
  + Γ_selectなし
  ↓
status = underdetermined
selected target = None
```

target候補集合が複数あるため、候補を保持するだけで選択しない。

### 3.2 選択規則あり

今回のfixture用に、次の限定的な選択規則を置く。

```text
Γ_select:
  prefer_primary_tonic_resolution
```

これを適用すると、`source = primary` として外部入力された候補を選ぶ。

```text
dominant_candidate
  + {C major(primary), A minor(alternative)}
  + Γ_select
  ↓
selected target = C major
```

これは一般的な和声機能規則ではない。選択境界を観測するためのfixture用規則である。

---

## ■ 4. 観測結果

| function annotation | target candidates | Γ_select | status | selected target | generated by function |
|---|---|---|---|---|---|
| `dominant_candidate` | `C major`, `A minor` | なし | `underdetermined` | `None` | `false` |
| `dominant_candidate` | `C major`, `A minor` | `prefer_primary_tonic_resolution` | `selected_target` | `C major` | `false` |

確認できたこと。

```text
function annotation candidate
  ≠ target candidate generation

target candidate set
  ≠ selected target

selection policy
  + target candidate set
  → selected target
```

今回のfixtureでは、`Γ_select`はfunction annotationを再参照せず、外部候補に付与された`source`属性だけを読む。したがって、function annotationはtarget候補生成器ではなく、今回の選択controllerでもない。

---

## ■ 5. Module責務の確認

今回の接続は、次のように分かれる。

```text
和声機能Module:
  dominant_candidateを渡す

target候補境界:
  外部入力されたtarget候補集合を保持する

選択境界:
  明示されたΓ_selectがある場合だけselected targetへ進む

声部進行Module:
  今回は未接続
```

今回の経路では、selected targetが生じた後に声部進行Moduleへ渡す。

---

## ■ 6. まだ言えないこと

今回の検証から、次は言えない。

```text
dominant_candidateからtarget候補集合が生成できること
C majorが常に正しい解決先であること
deceptive resolutionの一般規則
選択規則の起源
selected targetから具体音が決まること
voice leading後にnext key contextが決まること
```

今回のtarget候補集合と`Γ_select`はfixture用であり、一般的な和声機能規則ではない。

これらは未解決ξとして残す。

## ■ 7. 暫定結論

43では、42で停止していたfunction annotation候補の後段に、外部入力されたtarget候補集合を接続した。

```text
function annotation candidate
  + target candidate set
  ↓
target candidates observed
```

ただし、候補集合を観測しただけではtargetは選択されない。

```text
{C major, A minor}
  ↓ Γ_selectなし
underdetermined
```

明示された選択規則がある場合だけ、selected targetへ進む。

```text
{C major, A minor}
  + Γ_select（限定fixture）
  ↓
selected target = C major
```

したがって、42〜43で次の三分離を確認した。

```text
function annotation
  ≠ target candidate generation
  ≠ target selection
```

次の検証では、selected targetを声部進行Moduleへ渡した場合に、target degreeとconcrete pitch realizationがどこで分かれるかを見る。
