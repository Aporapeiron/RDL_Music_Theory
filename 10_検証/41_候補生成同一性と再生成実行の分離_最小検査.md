# 検証記録：候補生成同一性と再生成実行の分離

*対象：音程Moduleのno_effect fallback record*  
*状態：DRAFT v0.1 / 比較判定を処理省略へ使わない検査*

40により、no_effect record前後のstateは候補生成用途では同一と比較できる。

```text
same_for_candidate_generation(source, resulting) = True
```

41では、この比較結果が再生成処理の省略を意味しないことを既存36・37の呼出し側で固定する。

```text
same_for_candidate_generation = True
  ≠ transition record不要
  ≠ state_after_transition不要
  ≠ regenerate_candidate_branches不要

recordを使う再生成は実行する
  → source / resulting候補結果は今回fixtureで一致
```

このassertは最適化規則を追加しない。候補生成入力以外にcontroller入力・履歴・record存在が残るため、比較用の同一性から処理省略の安全性は導けない。
