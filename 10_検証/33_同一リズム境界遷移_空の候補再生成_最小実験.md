# 検証記録：同一リズム境界遷移と空の候補再生成

*対象：リズムModuleの`BoundaryTransition`*  
*状態：DRAFT v0.1 / 構造遷移後の空再生成検証*

---

## ■ 0. 目的

32では、音程Moduleで実差分を持つ構造遷移recordが再生成へ接続しても、結果は空になり得ることを確認した。

33は同じ結果分離をリズムModuleで確認する。26専用の動的候補生成器は`grid_open=False → True`により候補語彙を開くが、その後のModule固有制約は空を返し得る。

```text
BoundaryTransition
  grid_open: False → True
  ├─ project_boundary_transition
  │    → structural_transition / not_realized
  └─ dynamic_candidate_space
       → (表拍, 裏拍, 休符)
       → current=休符 の除外 + target=休符
       → empty
```

## ■ 1. 同一recordと実差分

`BoundaryTransition`は次を保持する。

```text
source_grid_open=False
resulting_grid_open=True
```

したがって投影eventは`operation_status=applied`、`change_axes=(grid_boundary_changed,)`となる。候補生成は操作名ではなく、recordの`resulting_grid_open`を読む。

## ■ 2. 再生成と制約結果

再生成直後の候補空間は、次の通り開いている。

```text
(表拍, 裏拍, 休符)
```

ただし今回の制約は、現在の`休符`を除外し、同時に`target=休符`を要求する。

```text
regeneration_status          = executed
raw_candidate_space          = (表拍, 裏拍, 休符)
raw_candidate_space_count    = 3
constrained_candidates       = ()
constrained_candidate_count  = 0
status                       = no_candidate
```

これは構造遷移が無効だったことを意味しない。構造遷移後の候補空間と、現在値・targetによる制約の交差が空であるというModule固有の観測である。

## ■ 3. 確定範囲

```text
構造遷移recordの実差分
  → structural_transitionへの投影
  → record由来の候補再生成
  → Module固有制約後はempty
```

音程32とリズム33により、`regeneration_status=executed`と最終結果が非空であることは二標本で別軸として扱える。ただし33の`raw_candidate_space`と`constrained_candidates`はリズムModule固有の分解であり、共通字段へは昇格しない。
