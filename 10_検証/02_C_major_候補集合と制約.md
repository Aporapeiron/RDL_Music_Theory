# 検証記録：C majorの候補集合と制約

*対象：`01_RDL音楽_Core.md`の保存・変更操作*  
*状態：DRAFT v0.2 / 正式Module化前の実験*  
*実装：`10_検証/c_major_operations.py`*

---

## ■ 0. 検証目的

前回の実験では、`stabilize / destabilize / shift` をC majorへ割り当て、候補の順位を生成した。

ただし、その結果は、Coreの操作が音楽的な安定や不安定を自然に導いたことの証明ではない。C major側で順位規則を定義し、その規則どおりの出力を得た実装実験だった。

今回は操作語の意味を増やさず、もっと小さい構造だけを確認する。

```text
候補空間
+ Bの保存条件
+ 現在候補の変更
+ 目標条件
↓
候補集合
```

目的は、操作から音を一意に生成することではなく、条件が不足したときに候補集合と未決定性をそのまま返せるかを見ることである。

---

## ■ 1. 境界と候補空間

今回の参照境界を、C majorの音高クラス集合として置く。

```text
B_Cmaj:
  tonic = 0
  scale = {0, 2, 4, 5, 7, 9, 11}
```

候補は、まず12平均律上の根位置三和音に限定する。これは音楽一般の候補空間ではなく、今回の実験用の閉じた集合である。

```text
quality:
  major       = (0, 4, 7)
  minor       = (0, 3, 7)
  diminished  = (0, 3, 6)
```

`preserve(B_Cmaj)` を適用した候補空間は、構成音がすべてC majorの音高クラス集合に含まれる根位置三和音である。

| 度数 | 候補 | root | quality | pcs |
|---:|---|---:|---|---|
| 1 | I / C | 0 | major | {0, 4, 7} |
| 2 | ii / Dm | 2 | minor | {2, 5, 9} |
| 3 | iii / Em | 4 | minor | {4, 7, 11} |
| 4 | IV / F | 5 | major | {0, 5, 9} |
| 5 | V / G | 7 | major | {2, 7, 11} |
| 6 | vi / Am | 9 | minor | {0, 4, 9} |
| 7 | vii° / Bdim | 11 | diminished | {2, 5, 11} |

この7候補は、今回の境界と三和音の定義から機械的に残る集合である。ここから「安定」「緊張」「機能」の意味は導入しない。

`preserve(B_Cmaj)` を外すと、12根音×3種類、合計36候補へ拡張する。これは境界を外したときに候補空間が広がることを確認するための実験上の設定であり、クロマティックな音楽全体を記述したものではない。

---

## ■ 2. 最小操作：現在候補を変更する

現在候補を `I / C` とし、Coreの `change()` に対応する最小の条件を次のように置いた。

```text
current = I / C
change(current)
preserve(B_Cmaj)
target = 未指定
```

結果は次の6候補である。

```text
{ii / Dm, iii / Em, IV / F, V / G, vi / Am, vii° / Bdim}
```

ここで、`change(current)` だけから移行先は一意に定まらない。実装は候補を一つ選ばず、`status = underdetermined` を返す。

候補数に基づく状態は、`target` の指定有無ではなく、制約適用後の集合そのものから判定する。

```text
|C| = 0  → no_candidate
|C| = 1  → locally_resolved
|C| > 1  → underdetermined
```

したがって、`target` が未指定でも候補が一つなら `locally_resolved` となる。逆に、`target` を指定しても候補が空なら、一意化ではなく `no_candidate` である。

ここでの `locally_resolved` は、宣言したC major境界・候補空間・制約の内部で一候補に絞られたことを表す。音楽的に唯一正しいことを意味しない。同様に、`no_candidate` はこの実験条件における解なしであり、直ちに理論や音楽構造の破断を意味しない。

---

## ■ 3. 目標条件を追加する

同じ条件に目標を加える。

```text
current = I / C
change(current)
preserve(B_Cmaj)
target = V / G
```

結果は、次の一候補になる。

```text
{V / G}
```

ここでVが「自然に選ばれた」のではない。目標条件によって候補集合が絞られたのである。

---

## ■ 4. 保存条件を外す

現在候補の変更だけを残し、`preserve(B_Cmaj)` を外す。

```text
current = I / C
change(current)
preserve(B_Cmaj) = なし
target = 未指定
```

候補空間は36候補となり、現在の `I / C` を除いた35候補が残る。

```text
36候補
− 現在候補1つ
= 35候補
```

したがって、保存条件は順位付けの補助ではなく、何を候補として数えるかそのものに作用する。

---

## ■ 5. 今回確認できた構造

今回の実装で確認できたのは、次の範囲である。

```text
操作条件
+ 境界 B
+ 候補空間
+ 保存条件
+ 変更条件
+ 目標条件
↓
候補集合
```

より具体的には、次が成立した。

| 条件 | 結果 |
|---|---|
| C majorを保存し、現在候補を変更 | 6候補 |
| 上記にVという目標を追加 | 1候補 |
| C majorを保存せず、現在候補を変更 | 35候補 |
| 6候補が残る | `status = underdetermined` |
| 1候補が残る | `status = locally_resolved` |
| 候補が空になる | `status = no_candidate` |

これは、Coreの操作語が音を直接命令するというより、境界と条件を通じて候補空間へ制約を掛ける上位操作として実装できる可能性を示す。

ただし、これは今回のC majorモデルで得た実装上の観察であり、Coreへ追加する確定原理ではない。別の単純事例でも同じ構造が残るかを確認する必要がある。

## ■ 6. 今回扱わなかったもの

今回の検証では、次を使わなかった。

```text
stabilize / destabilize
tonic_overlap
tonic_delta
転回形・ボイシング
七の和音
声部進行
コードの持続・反復
前後の履歴
聴覚的な安定・緊張・不快
```

特に、`tonic_overlap` を置かないことで、安定を主和音との共有音数へ直結させる構造をいったん避けた。

## ■ 7. 未回収ξ

今回の候補集合モデルからは、次が未回収である。

```text
同じ候補が実際にどう聞かれるか
候補の順序を何が決めるか
目標が明示されない場合の選択
時間的な反復と履歴
音域・配置・低音
別の境界で同じ制約構造が保つか
```

この未回収分を、安定度や緊張度という新しい数値へ直ちに変換しない。

---

## ■ 8. 暫定結論

```text
候補集合は、境界と保存条件によって変わる。
change(current)だけでは移行先は一意に定まらない。
目標条件を追加すると候補集合を絞れる。
候補数に応じて、`underdetermined`・`locally_resolved`・`no_candidate` を区別できる。
```

現時点では、これを調性・和声Moduleとして抽出しない。複数の単純事例で同じ構造が再現され、C major固有の定義から分離できた時点で、Module化の必要性を再評価する。
