# 検証記録：単純リズムの候補集合と制約

*対象：C majorとは別の単純事例における候補集合モデル*  
*状態：DRAFT v0.1 / 正式Module化前の実験*  
*実装：`10_検証/rhythm_candidate_operations.py`*

---

## ■ 0. 検証目的

C majorの実験で得られた候補集合の状態判定が、和声固有の語彙なしでも成立するかを確認する。

今回は、4/4の一定グリッド上の一つの位置だけを扱う。候補は表拍と裏拍に閉じ、音高・和声・アクセント・テンポ・グルーヴは導入しない。

```text
B
+ 候補空間
+ 現在候補の変更
+ 目標条件
↓
候補集合
↓
候補数による状態
```

ここでの目的は、リズム理論を作ることではない。`target` が未指定でも候補が一つになれば `locally_resolved` と判定できるかを見ることである。

---

## ■ 1. 境界と候補空間

```text
B_4/4:
  meter = 4/4
  grid = 一定グリッド

候補 = {表拍, 裏拍}
```

この候補空間は、今回の境界に対応する実験用の閉じた集合である。4/4拍子一般や、実際の演奏におけるアクセント全体を記述するものではない。

---

## ■ 2. 現在候補を変更する

現在候補を表拍とし、変更条件だけを適用する。

```text
current = 表拍
change(current)
target = 未指定
```

結果は次の一候補になる。

```text
{裏拍}
```

この場合、`target` は未指定だが候補数が1なので、状態は `locally_resolved` である。

```text
|C| = 1 → locally_resolved
```

したがって、`target未指定` と `underdetermined` は同義ではない。状態は目標条件の有無ではなく、制約適用後の候補集合の大きさから判定される。

ここでの `locally_resolved` は、今回宣言した候補空間の内部で一候補に絞られたことを表す。音楽的に唯一正しいことを意味しない。`no_candidate` も、4/4・一定グリッド・2候補という実験条件における解なしを表す。

---

## ■ 3. 解なしの条件

変更後の候補に存在しない休符を目標に指定する。

```text
current = 表拍
change(current)
target = 休符
```

結果は空集合になる。

```text
∅ → no_candidate
```

これは一意化ではなく、今回の候補空間・境界・目標条件の組み合わせでは解がないことを示す。

---

## ■ 4. C major実験との対応

| 条件 | 結果 |
|---|---|
| `target` 未指定、変更後に2候補以上 | `underdetermined` |
| `target` 未指定、変更後に1候補 | `locally_resolved` |
| 指定条件が候補空間と衝突 | `no_candidate` |

この事例では、C majorで使った音高・和音・度数の定義を使わずに、候補数による三状態を確認できた。

ただし、候補集合を作る方法自体は各事例に依存している。今回の結果だけで、共通の生成器やCoreの新しい操作を確定しない。

## ■ 6. 暫定結論

```text
C majorの候補集合モデルで観測された三状態は、
単純なリズム候補にも再現できた。
```

現時点で観測されたのは、次の一般的な最小構造である。

```text
制約適用
↓
候補集合 C
↓
|C| による状態判定
```

これはRDL音楽固有のCore追加候補ではなく、既存の制約適用道具として扱う。次は一般側の事例を増やすのではなく、音楽における `B` と `C(B)` の生成へ戻る。
