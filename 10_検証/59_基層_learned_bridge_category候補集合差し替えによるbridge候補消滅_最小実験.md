# 検証記録：基層-learned bridge・external learned候補集合差し替えによるbridge候補消滅

*対象：同じhuman-side response differenceと同じΓ_bridgeで、external learned category candidatesだけを差し替えたときbridge候補が分岐または消滅する条件*  
*状態：DRAFT v0.1 / 58 Γ_bridge差し替え検証後の候補集合差し替え最小検証*  
*実装：`10_検証/base_to_learned_bridge_candidate_set_variation.py`*

---

## ■ 0. 検証目的

58では、同じhuman-side response differenceと同じexternal learned category candidatesでも、`Γ_bridge`を差し替えるとbridge候補が分岐することを確認した。

59では、human-side response differenceと`Γ_bridge`を固定し、external learned category candidatesだけを差し替える。

```text
same human-side response difference
  + same Γ_bridge_fixture
  + different external learned category candidates
  ↓
bridge candidate observed / no bridge candidate observed
```

ここで確認するのは、bridge候補がresponse differenceとΓだけで決まるのではなく、外部候補集合の内容にも依存することである。

---

## ■ 1. 固定するhuman-side response difference

57〜58と同じA2系のhuman-side response differenceを使う。

```text
human-side response difference:
  label = A2 behavioral discriminability difference
  source_base_candidate = frequency_difference_to_behavioral_discriminability_candidate
  response_axis = behavioral_discriminability
  lower_response = low_discriminability
  higher_response = high_discriminability
  generated_learned_category = None
```

これは弁別応答差であり、pitch categoryや音程認識ではない。

---

## ■ 2. 固定するΓ_bridge

58で使ったdifference label側のfixture Γを固定する。

```text
Γ_bridge_discriminability_to_difference_label_fixture:
  A2 behavioral discriminability difference
  + external candidates
  → different_pitch_relation_label_candidate をbridge候補として読む
```

このΓは一般的なcategory generation ruleではない。半音知覚、音程認識、音名生成の規則でもない。

---

## ■ 3. 差し替えるexternal learned category candidates

二つの候補集合を比較する。

```text
candidate set A:
  same_pitch_relation_label_candidate
  different_pitch_relation_label_candidate
```

```text
candidate set B:
  same_pitch_relation_label_candidate
  uncertain_pitch_relation_label_candidate
```

どちらも外部fixture候補であり、response differenceから生成しない。

```text
external learned category candidates
  ≠ generated by response difference
```

---

## ■ 4. 最小ケースの比較

### 4.1 target candidateを含む候補集合

```text
same response difference
+ same Γ_bridge
+ candidate set A
↓
bridge candidate = different_pitch_relation_label_candidate
```

### 4.2 target candidateを含まない候補集合

```text
same response difference
+ same Γ_bridge
+ candidate set B
↓
no_bridge_candidate_observed
```

candidate set Bでは、Γが読む対象候補が外部候補集合に存在しないため、bridge候補は観測されない。

---

## ■ 5. 観測結果

| human-side response difference | Γ_bridge | external candidates | status | bridge candidate |
|---|---|---|---|---|
| same | same | set A includes `different_pitch_relation_label_candidate` | `bridge_candidate_observed_not_selected` | `different_pitch_relation_label_candidate` |
| same | same | set B excludes `different_pitch_relation_label_candidate` | `no_bridge_candidate_observed` | none |

確認できたこと。

```text
same human-side response difference
same Γ_bridge
different external learned category candidates
↓
bridge candidate observed / no bridge candidate observed
```

したがって、bridge候補はhuman-side response differenceとΓだけでは決まらない。

```text
bridge candidate
  ≠ human-side response difference の属性
  ≠ Γ_bridge 単体の属性
  ≠ generated learned category
  ≠ selected musical interpretation
```

---

## ■ 6. Module責務の確認

今回の接続は、次のように分かれる。

```text
基層候補側:
  同じhuman-side response differenceを渡す

Γ_bridge:
  同じbridge Γを渡す

learned側:
  external learned category candidatesを差し替える

bridge候補:
  候補集合に対象候補がある場合だけ観測される

中核音楽理論:
  今回は未接続
```

したがって、learned候補集合の構成もbridge成立条件の一部である。

---

## ■ 7. まだ言えないこと

今回の検証から、次は言えない。

```text
different_pitch_relation_label_candidateが正しいlearned categoryであること
候補集合にないcategoryを生成してよいこと
bridge候補がselected musical interpretationであること
Γ_bridgeの採用条件が決まったこと
learned category候補集合の生成規則が決まったこと
周波数弁別からpitch categoryが生成されたこと
音程認識が説明されたこと
```

また、今回の候補集合と`Γ_bridge`はfixture用であり、一般的なbase-to-learned mappingではない。

---

## ■ 8. 暫定結論

59では、同じhuman-side response differenceと同じ`Γ_bridge`でも、external learned category candidatesを差し替えるとbridge候補が観測されたり消滅したりすることを確認した。

```text
bridge candidate
  = C(human-side response difference, external learned category candidates; Γ_bridge_fixture)
```

ただし、これはfixture内の限定表現である。bridge候補はlearned category生成でも、音楽解釈選択でもない。

57〜59をまとめると、base-to-learned bridgeは少なくとも次の三者関係として扱う必要がある。

```text
human-side response difference
× external learned category candidates
× Γ_bridge
→ bridge candidate
```

次に進むなら、57〜59を一度構造抽出し、`ξ_base_to_learned_bridge` の現在地を圧縮する。
