# 検証記録：文脈解釈・voice leading後のnext key未確定

*対象：44で得たvoice leading resultを、next key/context interpretationへ直結しない条件*  
*状態：DRAFT v0.1 / 44の後続接続検証*  
*実装：`10_検証/next_key_context_after_voice_leading_boundary.py`*

---

## ■ 0. 検証目的

42〜44では、次の分離を確認した。

```text
function annotation
  ≠ target candidate generation
  ≠ target selection
  ≠ target degree planning
  ≠ concrete pitch realization
```

45では、この後段で次の短絡を避ける。

```text
voice leading result
  ≠ next key/context interpretation
```

44で得た具体音実現結果を受け取るが、その結果から次のkey contextを自動確定しない。

今回確認するのは、次である。

```text
voice leading result
  + externally supplied next context candidate set
  ↓
next context candidates observed
  ↓
Γ_context_selectionなし → underdetermined
Γ_context_selectionあり → selected next context
```

---

## ■ 1. 固定する最小入力

44から次を受け取る。

```text
selected target = C major
selected concrete target = E4-C5
motion = -1 / +1 semitone
```

これは既存14の具体音実現構造へ接続した結果である。

ただし、`E4-C5` や motion からnext key/contextを生成しない。

---

## ■ 2. 外部から与えるnext context候補集合

今回は外部fixtureとして、二つのnext context候補を与える。

```text
next context candidates:
  C major continuation
  A minor reinterpretation
```

この候補集合は、voice leading resultから生成されたものではない。

```text
generated_by_voice_leading = false
```

---

## ■ 3. BとΓ

今回の境界は次の通り。

```text
B_context_interpretation:
  voice leading result
  externally supplied next context candidate set
  optional selection policy
```

使うΓは、候補の観測と選択を分ける。

```text
Γ_context_observation:
  voice leading result + next context candidate set
  → next context candidates observed

Γ_context_selection:
  next context candidate set + selection policy
  → selected next context
```

ここで重要なのは、次を置かないことである。

```text
Γ_next_key_generation_from_voice_leading
Γ_modulation_detection
Γ_formal_interpretation
```

したがって、voice leading resultはnext key/context生成器ではない。

---

## ■ 4. 最小ケース

### 4.1 selection policyなし

```text
voice leading result = E4-C5
  + {C major continuation, A minor reinterpretation}
  + Γ_context_selectionなし
  ↓
status = underdetermined
selected next context = None
```

候補があることは、選ばれていることを意味しない。

### 4.2 selection policyあり

今回のfixtureでは、`Γ_context_selection` はvoice leading resultを再参照せず、外部候補に付与された `source` 属性だけを読む。

```text
selection policy = prefer_continuation_fixture
  + next context candidate set
  ↓
selected next context = C major continuation
```

したがって、今回のfixtureでは、voice leading resultはnext context候補生成器ではなく、選択controllerでもない。

voice leading result

## ■ 6. Module責務の確認

今回の接続は、次のように分かれる。

```text
具体音実現境界 / 44:
  E4-C5というvoice leading resultを渡す

文脈解釈境界 / 45:
  外部fixtureとしてnext context候補集合を受け取る

controller:
  Γ_context_selectionが明示された場合だけ
  selected next contextを作る
```

45は、voice leading後の文脈解釈境界を確認する検証であり、転調理論、形式理論、聴取上の調性感判定器を新設しない。

---

## ■ 7. まだ言えないこと

今回の検証から、次は言えない。

```text
E4-C5からC major continuationが自動生成されること
voice leadingの滑らかさが調性継続を意味すること
A minor reinterpretationが実際に聴取上成立すること
転調や借用和音が検出できること
形式Moduleがnext contextを確定できること
次時刻のkey contextをどのcontrollerが選ぶか
```

next context候補集合はfixtureであり、選択規則もfixture用の限定Γである。

これらは未解決ξとして残す。

---

## ■ 8. 暫定結論

45では、44で得たvoice leading resultを、next key/context interpretationへ直結しない条件を確認した。

```text
voice leading result = E4-C5
  ↓ external next context candidate set
next context candidates observed
  ↓ Γ_context_selectionなし
underdetermined
```

明示されたselection policyを与えた場合だけ、fixture内でselected next contextが生じる。

```text
next context candidates observed
  + Γ_context_selection
  ↓
selected next context = C major continuation
```

ただし、この選択はvoice leading resultから生成されたものではない。

したがって、42〜45で次の分離が確認された。

```text
function annotation
  ≠ target candidate generation
  ≠ target selection
  ≠ target degree planning
  ≠ concrete pitch realization
  ≠ next key/context interpretation
```

次の検証では、42〜45を圧縮し、中核音楽理論横断の接続地図として、どのξを `20_構造抽出` へ送るかを見る。
