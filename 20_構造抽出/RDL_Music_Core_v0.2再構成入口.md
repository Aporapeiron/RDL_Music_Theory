# RDL Music Core v0.2 再構成入口

## 位置づけ

T2候補の抽出が進んだあと、RDL_Music_Theoryを再び音楽固有理論として立て直すための入口である。

Musicは、汎用代謝実行機構を発見するための実験場だけではない。

```text
RDL Music =
  音楽について何が見えるか
  音楽をどう変形できるか
  聴こえの変化をどこまで予測できるか
```

を扱うT3音楽応用系である。

## 停止線

今後のMusic本線では、汎用状態遷移だけを目的にした新規50工程列を原則増やさない。

既存の長大なB分類検証列は削除しない。

```text
既存3398工程
≠ Music本線として無限継続する工程列
```

既存列は、T2候補の発生源・証拠・historical fixtureとして保存する。

## Music側に残す問い

RDL Music Core v0.2で中心に置く問い:

```text
1. 音楽的境界
   何を音楽的単位・基準として切り出しているか。

2. 音楽的関係
   どの関係が現在の聞こえを支配しているか。

3. 保存されるもの
   何が同一性として残っているか。

4. 変化するもの
   何が動き、どの関係が変わったか。

5. 状態遷移
   どの音楽状態からどの状態へ移ったか。

6. 複数解釈
   どの聞こえが同時に残り、どれが前景化したか。

7. 分析
   現在の音楽状態をどう記述できるか。

8. 生成
   保存条件と変化条件から別の音楽状態を作れるか。
```

## 三本柱

Music側の本線作業は、当面以下に絞る。

```text
A. 音楽固有Coreを圧縮する

B. 実際の音楽を分析する

C. 分析結果を使って音楽を生成・変形する
```

ここでCを必須にする。

分析だけで止まるなら、RDL Musicは既存理論の再記述に寄りすぎる。

```text
分析できる
↓
関係を抽出できる
↓
保存条件を指定できる
↓
変化条件を指定できる
↓
別の音楽を生成できる
```

までをMusic側の検査対象にする。

## 小さい実音楽ループ

今後のMusic固有検証は、工程数を増やすより、一つの音楽対象に対して小さく一周させる。

```text
Bを置く
↓
関係を抽出
↓
保存関係を指定
↓
一つだけ変える
↓
生成
↓
聴取上どう変わったか確認
↓
Music Coreを修正
```

これはT2抽出のための長大工程列ではなく、音楽について答えを返すための検証である。

## 初期対象領域

v0.2では、全領域を同時に埋めない。

まず以下の三領域を使う。

```text
音高・音程
和声機能・声部進行
リズム・拍節
```

これらで、分析、予測、変形、再聴取を一周させる。

```text
analysis
↓
prediction
↓
transformation
↓
re-hearing
```

## 操作例

Music v0.2で検査する操作候補:

```text
この旋律の同一性を保ったまま、拍節だけ変える。

この和声進行の方向性を保ったまま、調律系を変える。

このフレーズの曖昧性を増やす。

C6として安定していた関係を、Am7側へ徐々に傾ける。
```

これらは、candidate / selection / commitment / recordを精密化するための例ではない。

```text
何を保存し、
何を変えると、
どんな音楽状態へ移るか
```

を検査するための例である。

## T2との関係

T2候補はMusicから剥がしてよい。

ただし、Musicから消すわけではない。

```text
Music Core
  音楽固有の境界・関係・保存・変化・生成を扱う。

Music fixture
  T2 Mechanismが音楽対象で動くかを検査する。

T2 extraction history
  既存の長大検証列を、汎用機構発見の証拠として保存する。
```

T2を抜くことだけを目的にすると、Musicは空洞化する。

Music側は、T2を利用しながら、音楽的問いへ戻る。

## 論理配置

物理移動はまだ行わないが、論理的には以下の扱いに切り替える。

```text
10_検証
  Music固有検証

20_構造抽出
  Music構造抽出
  T2候補抽出

50_Music_T2_fixtures
  将来の接続fixture候補

90_T2抽出元_historical
  既存3398工程の長大列
```

現段階では、既存ファイルを大量移動しない。

## 破断条件

次の場合、Music v0.2再構成は失敗として扱う。

```text
MusicがT2候補抽出だけを続け、音楽的分析・生成へ戻れない。

既存音楽理論のラベル再記述だけになり、保存・変化・生成条件を返せない。

分析はできるが、変形または生成に使えない。

生成はできるが、何を保存し何を変えたか説明できない。

T2 MechanismをMusic Core primitiveとして再吸収してしまう。
```

## 次の検査

次は、小さい実音楽ループを一つ選び、Music側の本線を再開する。

候補:

```text
C6 / Am7 の安定関係を、保存・変化条件で遷移させる。

短い旋律の輪郭を保ったまま、拍節だけを変える。

同じ和声方向を保ったまま、声部進行または調律系を変える。
```

ここでは50工程化しない。

Music Core v0.2に必要な最小更新だけを返す。
