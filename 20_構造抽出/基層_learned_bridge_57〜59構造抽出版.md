# 基層-learned bridge｜57〜59構造抽出版

*対象：57〜59で確認した、human-side response differenceからlearned category候補へ接続するbridge境界*  
*状態：DRAFT v0.1 / 54〜56基層候補構造抽出後のbridge局所構造抽出*

## ■ 0. 位置づけ

本書は、57〜59の最小検証列から、`ξ_base_to_learned_bridge` の現在地を抽出する。

54〜56では、human-side response differenceをlearned musical categoryへ接続しなかった。

57〜59では、human-side response difference、external learned category candidates、`Γ_bridge`を分け、次の関係としてbridge候補だけを観測した。

```text
human-side response difference
  + external learned category candidates
  + Γ_bridge_fixture
  ↓
bridge candidate observed
  ↓
selected musical interpretationは未生成
```

本書は、音楽学習モデル、音程認識モデル、category generation ruleを追加しない。fixture列から見えた責務境界だけを圧縮する。

## ■ 1. 抽出された接続地図

```text
human-side response difference ─────┐
  └─ behavioral discriminability     │
                                     ├→ bridge compatibility check
external learned category candidates ┤
  ├─ same label candidate            │
  ├─ different label candidate       │
  └─ uncertain label candidate       │
                                     │
Γ_bridge_fixture ────────────────────┘
                                     ↓
                            bridge candidate observed
                                     │
                                     │ learned categoryを生成しない
                                     │ selected interpretationへ自動昇格しない
                                     ↓
                         ξ_category_generation_boundaryへ保持
```

この地図は、human-side response differenceからlearned categoryが直に生えることを示さない。learned候補集合も、response differenceから生成されたものではなく、外部入力として扱う。

## ■ 2. 検証ごとの担当

| 検証 | 担当する範囲 | 確認した境界 |
|---|---|---|
| 57 | response difference + external candidates + Γ_bridge | Γなしではunderdetermined、Γありでbridge候補を観測 |
| 58 | same response difference + same candidates + different Γ_bridge | Γ_bridge差し替えでbridge候補が分岐 |
| 59 | same response difference + same Γ_bridge + different candidates | 候補集合差し替えでbridge候補が観測 / 消滅 |

## ■ 3. 保持する非同一性

57〜59から、次の非同一性を保持する。

```text
human-side response difference
  ≠ generated learned category

external learned category candidates
  ≠ generated by response difference

external learned category candidates
  ≠ bridge candidate

Γ_bridge fixture
  ≠ 一般category generation rule

bridge candidate
  ≠ confirmed learned category
  ≠ selected musical interpretation

bridge candidate observed
  ≠ learned category selection
```

特に重要なのは、bridge候補がresponse側の属性でも、learned候補集合側の属性でも、Γ単体の属性でもないことである。

## ■ 4. 依存関係として見えた形

fixture内では、bridge候補は次の関係として読むのが堅い。

```text
bridge candidate
  = C(human-side response difference, external learned category candidates; Γ_bridge_fixture)
```

ただし、これは一般式ではない。57〜59のfixtureでは、A2 behavioral discriminability differenceを入力にし、learned pitch relation label候補集合を外部入力として読んだ。

58ではΓ_bridgeの差し替えで候補が分岐し、59では候補集合の差し替えで候補が消滅した。したがって、bridge候補は三者関係として扱う必要がある。

```text
human-side response difference
× external learned category candidates
× Γ_bridge
→ bridge candidate
```

## ■ 5. 確定接続

**57**：A2 behavioral discriminability differenceとexternal learned category candidatesを接続しても、Γ_bridgeなしでは `underdetermined_without_bridge_gamma` となる。`Γ_base_to_learned_bridge_fixture` を与えた場合だけ、`different_pitch_relation_label_candidate` がbridge候補として観測される。selected musical interpretationは生成しない。

**58**：同じhuman-side response differenceと同じexternal candidatesでも、Γ_bridgeを差し替えると `different_pitch_relation_label_candidate` と `uncertain_pitch_relation_label_candidate` へbridge候補が分岐する。

**59**：同じhuman-side response differenceと同じΓ_bridgeでも、external learned category candidatesから `different_pitch_relation_label_candidate` を外すと、`no_bridge_candidate_observed` となる。

いずれも、generated learned category、confirmed learned category、selected musical interpretationは生成していない。

## ■ 6. 未解決ξ

57〜59の後に残る主なξは次である。

```text
ξ_bridge_gamma_selection:
  どのΓ_bridgeを採用するか

ξ_bridge_gamma_origin:
  Γ_bridgeの由来、文化差、学習差、記述体系差

ξ_learned_candidate_generation:
  external learned category candidatesをどこから生成・供給するか

ξ_learned_candidate_scope:
  候補集合にどのcategory familyを含めるか

ξ_bridge_applicability_condition:
  human-side response differenceのどの特徴をbridge条件として読むか

ξ_bridge_candidate_prioritization:
  複数bridge候補が観測された場合にどう順序付けるか

ξ_bridge_selection_controller:
  bridge候補からselected musical interpretationを選ぶcontroller

ξ_category_confirmation_condition:
  bridge候補をconfirmed learned categoryへ昇格できる条件
```

これらは現段階でCoreへ上げない。learned category候補生成、文化差・学習差、selection controller、中核音楽理論との接続で扱う。

## ■ 7. 禁止補完

```text
human-side response differenceからlearned categoryを自動生成しない
learned候補集合をresponse differenceの産物とみなさない
Γ_bridgeの存在を一般category generation ruleの完成とみなさない
bridge候補をconfirmed learned categoryとみなさない
bridge候補をselected musical interpretationとみなさない
候補集合にないlearned categoryをbridge側で生成しない
周波数弁別からpitch categoryやsemitone categoryを直接生成しない
音程認識・音名・調性をbridge候補から自動生成しない
各Γ_bridge・candidate set・controllerをCoreへ昇格しない
```

## ■ 8. 現時点の読み方

57〜59の成果は、base-to-learned bridgeを完成させたことではない。

むしろ、基層側のhuman-side response differenceからlearned音楽カテゴリーへ向かう接続が、少なくとも三者関係として分解されることを確認したことである。

```text
base response
  ≠ learned category
  ≠ bridge candidate
  ≠ selected musical interpretation
```

ここまでで、54〜56で停止していた境界は次のように一段だけ開いた。

```text
human-side response difference
  × external learned category candidates
  × Γ_bridge
  ↓
bridge candidate

──── ここで停止 ────

confirmed learned category
selected musical interpretation
中核音楽理論Moduleへの接続
```

この分離が保てる限り、後で文化差、学習差、命名体系差、記譜体系差、音楽理論Module側の候補集合を追加しても、基層応答そのものへlearned category生成を埋め込まずに済む。
