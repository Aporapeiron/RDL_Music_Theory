# 中核音楽理論｜42〜45循環分解の構造抽出版

*対象：42〜45で確認した、key / chord / function / target / voice leading / next context の循環候補分解*  
*状態：DRAFT v0.1 / 中核音楽理論横断レビューからの構造抽出*

## ■ 0. 位置づけ

本書は、42〜45の最小検証列から、中核音楽理論Module間の接続構造を抽出する。

新しい和声理論、声部進行理論、転調理論、形式理論は追加しない。

対象は、既知音楽理論では一本の流れに見えやすい次の循環候補である。

```text
key context
  ↓
chord candidate
  ↓
harmonic function
  ↓
target
  ↓
voice leading
  ↓
next key/context interpretation
```

42〜45では、この流れを自動閉包させず、各段階の責務境界を分けた。

## ■ 1. 抽出された接続地図

```text
key context
  ↓
chord candidate
  ↓
function annotation candidate
  │
  ├─ target候補を生成しない
  ↓
external target candidates
  ↓
selection boundary
  ↓
selected target
  │
  ├─ degree planを生成しない
  ↓
external degree plan
  ↓
existing realization pipeline
  ↓
voice leading result
  │
  ├─ next context候補を生成しない
  ↓
external next context candidates
  ↓
context selection boundary
  ↓
selected next context
```

この地図は因果列ではない。各矢印は、今回のfixtureで接続できた観測・候補・選択・実現の境界を示す。

## ■ 2. 検証ごとの担当

| 検証 | 担当する範囲 | 確認した境界 |
|---|---|---|
| 42 | same chord candidate + different key context | function annotation candidateはtargetを生成しない |
| 43 | function annotation + external target candidates | target候補集合とselected targetは同一ではない |
| 44 | selected target + external degree plan + existing 14 | selected targetはtarget degree planや具体音ではない |
| 45 | voice leading result + external next context candidates | voice leading resultはnext context生成器ではない |

## ■ 3. 保持する非同一性

42〜45から、次の非同一性を保持する。

```text
function annotation
  ≠ target candidate generation

target candidates
  ≠ selected target

selected target
  ≠ target degree plan

target degree plan
  ≠ concrete realization

voice leading result
  ≠ next context candidate generation

next context candidates
  ≠ selected next context
```

これらを一つでも潰すと、`key → chord → function → target → voice leading → next key` が未検証の因果列として閉じてしまう。

## ■ 4. 観測・生成・選択・実現・再解釈

42〜45の列は、次の責務分離として読む。

```text
annotation:
  degree annotation
  function annotation candidate

generation:
  target candidate generationは未実装
  next context candidate generationは未実装

observation:
  external target candidates observed
  external next context candidates observed

selection:
  selected target
  selected next context

planning:
  external target degree plan

realization:
  existing 14 realization pipeline
  concrete pitch pair

reinterpretation:
  next context interpretation candidate
```

ここで `generation` と書いた箇所は、今回の検証で生成器を作ったという意味ではない。むしろ、生成器を置かないまま候補集合を外部入力として受けた境界である。

## ■ 5. 確定接続

**42**：同一rooted chord candidateでも、key contextを変えるとroot degreeが変わり、fixture用の限定 `Γ_function_annotation` によってfunction annotation candidateが分岐する。

**43**：function annotation candidateに対して、外部target候補集合を接続できる。`Γ_select` がなければ `underdetermined`、明示policyがあればfixture内でselected targetが生じる。

**44**：43のselected targetを、外部target degree planを介して既存14の具体音実現pipelineへ接続できる。

**45**：44のvoice leading resultに対して、外部next context候補集合を接続できる。`Γ_context_selection` がなければ `underdetermined`、明示policyがあればfixture内でselected next contextが生じる。

## ■ 6. 未解決ξ

42〜45の後に残る主なξは次である。

```text
ξ_target_candidate_generation:
  function annotationからtarget候補集合を作る規則

ξ_target_selection:
  target候補集合からselected targetを選ぶcontroller

ξ_target_degree_planning:
  selected targetからtarget degree planを作る規則

ξ_realization_selection:
  具体音候補集合から実現を選ぶcontroller

ξ_next_context_generation:
  voice leading resultからnext context候補集合を作る規則

ξ_next_context_selection:
  next context候補集合からselected next contextを選ぶcontroller

ξ_hearing_context:
  聴取上の調性感・安定感・転調感との接続
```

これらは現段階でCoreへ上げない。必要なら、音階・調Module、和声機能Module、声部進行Module、形式Module、認知科学・脳物理側の後続検証へ分配する。

## ■ 7. 禁止補完

```text
dominant_candidateからtarget候補集合を自動生成しない
target候補があることをselected targetと同一視しない
selected targetからtarget degree planを自動生成しない
target degree planを具体音と同一視しない
voice leading resultからnext key/contextを自動確定しない
next context候補があることをselected next contextと同一視しない
```

## ■ 8. 現時点の読み方

42〜45の成果は、音楽理論の完成ではなく、循環しやすい中核音楽理論の接続を破断可能な境界へ分解したことである。

```text
annotation
  ≠ generation
  ≠ observation
  ≠ selection
  ≠ planning
  ≠ realization
  ≠ reinterpretation
```

この分離が保てる限り、後でtarget生成、声部進行controller、next context解釈、聴取上の調性感を追加しても、既存の検証列と衝突しない。
